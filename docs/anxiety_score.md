# anxiety_score - Heuristic, Not Clinical - Reproducible v0.1.1-pilot

Status: v0.1.1-pilot, n=1 simulated demo, unverified, heuristic only, NOT clinical, NOT a standard

## Formula (current pilot - actual code)

```
anxiety_score_heuristic = clamp(0.6 * sqrt(longest_pause_ms) + 0.4 * (deletion_count * 10), 0, 100)
clamp(x, 0, 100) = max(0, min(100, x))
sqrt(x) = x ** 0.5  (Python: longest_pause_ms ** 0.5)
deletion term = deletion_count * 10  (scales 0-10 deletions to 0-100)
the result is truncated with int() after the calculation
```

Actual code in `typing_demo.py`:

```
anxiety_heuristic = min(100, int(0.6 * (longest ** 0.5) + 0.4 * deletion_count * 10))
```

## Reproducible Example - simulated demo, 2026-10-27

Input (generated by the demo script, not observed from a person):

- typing_pauses = [1035, 1658, 2168, 5213] ms
- longest_pause_ms = 5213
- deletion_count = 4

Calculation:

- sqrt(5213) = 72.199...
- 0.6 * 72.199 = 43.319
- deletion_count * 10 = 40
- 0.4 * 40 = 16
- sum = 43.319 + 16 = 59.319
- int(59.319) = 59

Result: **59**, which matches the output of `typing_demo.py` and the README.

## Why not log? Why sqrt?

An early version of this document wrote: score = clamp(0-100, w1 * log(...) + w2 * ... + w3 * ...), with w1=0.6, w2=0.3, w3=0.1.

- The log base was not defined, w3 (revision_count) was never implemented, and deletion_rate = deletions / total keystrokes was never defined. It could not be reproduced.
- v0.1.1 fixes the document to match the code: sqrt dampens very long pauses without a log-base choice; w1=0.6 and w2=0.4 only; no w3.
- Future: a log vs sqrt comparison with a false-positive rate will be published when n >= 20.

## Why this is NOT anxiety

- The demo data is simulated with `sleep()`. It is NOT a real key hook, NOT a real user, with no inter-rater or test-retest checks.
- Real Chinese typing contains pauses that are not hesitation (for example Zhuyin candidate selection). Pinyin and English have different patterns. None of that is captured by simulated data.
- No false-positive rate and no clinical validation: no PHQ-9 or GAD-7 correlation, no clinician review.
- Deletion is recorded only as count and timing, not content. It is still a heuristic.
- NOT diagnostic, NOT for critical decisions: do NOT use for defense, law, drones, agriculture, weather, education, gaming, self-driving, space, or mental-health diagnosis.

## On-device only: requirements and how to verify

These are requirements, not yet proof:

- `core/` must have no network access: no `requests`, `httpx`, `openai`, `socket`, or fetch.
- No content logging: no `logger.info(user_message)`; only message length, hash, count, and timing.
- Opt-in is OFF by default, and the local buffer is purgeable.
- Planned check: a CI test that fails if `core/` imports a network library. Until it exists, treat the above as commitments.

Legacy cloud demo:

- The v0.1.0 cloud demo has been suspended (2026-10-29).
- Its `main.py` was fixed to remove content logging, add a webhook secret check, and add rate limiting. An earlier version of it did log message content, so any logs from that period should be deleted.
- Legacy files `api/`, `Procfile`, and `render.yaml` will move to `legacy_cloud_demo/` in the next commit. They are not part of the on-device core.
